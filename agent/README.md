# Agent Images

This directory builds the disposable harness images provisioned by Omashiki.
System behavior and security boundaries are documented in
[`docs/architecture.md`](../docs/architecture.md); this file covers only image
builds and container entrypoints.

## Build

```bash
mise run agent:build
mise run agent:claude:build
# OpenCode directly:
docker build -t omashiki/agent:latest agent/
# Claude Code 2.1.240 directly:
docker build -t omashiki/agent-claude:latest -f agent/Dockerfile.claude agent/
```

## OpenCode Image

`agent/Dockerfile` pins OpenCode and starts `opencode serve`. The orchestrator
creates and mounts the governed Git worktree before the image starts.

| Variable | Default | Description |
|---|---|---|
| `HOME` | `/tmp/agent-home` | Volatile writable home on the container tmpfs |
| `OPENCODE_PORT` | `4096` | Internal HTTP server port |
| `OPENCODE_CONFIG_CONTENT` | (empty) | Task-scoped override generated by the harness adapter |
| `OPENCODE_CONFIG_PATH` | (empty) | Read-only host config snapshot copied into volatile HOME |
| `OPENCODE_AUTH_PATH` | (empty) | Read-only auth snapshot copied into volatile HOME |
| `OMASHIKI_LLM_EGRESS_SOCKET` | (empty) | Unix socket for the restricted provider CONNECT proxy |
| `GIT_USER_NAME` | `omashiki-agent` | Git author name |
| `GIT_USER_EMAIL` | `agent@omashiki.local` | Git author email |

The entrypoint configures Git safe directories, copies declared OpenCode
configuration and authentication into volatile HOME, starts any required Unix-
socket relays, and then starts the HTTP server.

The runtime probes OpenCode's live `/doc` endpoint for readiness. The adapter
tests pin the subset of the upstream HTTP surface used by Omashiki.

## Claude Code Image

`agent/Dockerfile.claude` pins Claude Code `2.1.240`. Its entrypoint configures
Git, links the isolated credential state into volatile HOME, and stays idle.
Each harness turn is a separate Docker exec through
`omashiki-claude-runner`.

| Variable | Default | Description |
|---|---|---|
| `HOME` | `/tmp/agent-home` | Volatile writable home on the container tmpfs |
| `CLAUDE_CREDENTIALS_PATH` | `/run/omashiki/state/claude-credentials.json` | Isolated writable OAuth state file |
| `GIT_USER_NAME` | `omashiki-agent` | Git author name |
| `GIT_USER_EMAIL` | `agent@omashiki.local` | Git author email |

The runner reads a read-only invocation file, passes the prompt over stdin, and
starts Claude Code with fixed headless flags, no MCP/settings sources, and the
configured tool allowlist. The credential file is the only persistent writable
provider state; the provider's host configuration directory is never mounted.

## Runtime Boundary

Both images run as the repository owner IDs with a read-only root filesystem,
bounded tmpfs, dropped capabilities, no privilege escalation, and explicit
mounts supplied by the orchestrator. Do not add provider selection, credentials,
or arbitrary shell evaluation to an image entrypoint.
